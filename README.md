# 집킴이 (Zipkimi)

**CCTV 영상 속 두 사람의 '상대적 이동 관계'를 분석해 미행 가능성이 있는 구간을 선별하는 시스템**

> 본 시스템은 미행 여부를 **확정하지 않습니다.**
> 관제 담당자가 먼저 확인해야 할 영상 구간의 **우선순위를 제시**하며, 최종 판단은 사람이 수행합니다.

---

## 1. 왜 만들었나

- 관제요원 1인당 CCTV 담당 대수가 평균 약 **477대**로, 행정안전부 권고 기준(50대)의 약 10배
  → 사람이 모든 화면을 실시간으로 지켜보는 것은 불가능
- CCTV는 늘고 인력은 줄어드는 추세 (2022년 4,277명 → 2024년 4,093명)
- 스토킹은 `미행 → 접근 → 폭력` 순으로 심화되나, 대부분 사건 발생 후에야 영상을 되돌려 보며 확인
- 기존 지능형 CCTV(한화비전, 아이디스 등)는 배회·침입·쓰러짐 등 **'한 사람의 단독 이벤트'** 탐지가 중심
  → **'두 사람의 관계적 패턴(미행)'** 은 KISA 국가 인증 항목에도 아직 없는 영역

## 2. 무엇이 다른가

| 구분 | 기존 서비스 | 집킴이 |
|---|---|---|
| 지능형 CCTV | 한 사람의 단독 행동 탐지 | **두 사람의 상대적 이동 관계** 분석 |
| 스토킹 예방 앱 | 피해자가 직접 앱을 켜는 사후 대응 | 시스템이 선제적으로 선별하는 사전 예방 |
| 판정 방식 | 확정 판정 → 오탐 논란 | **위험도 단계화**, 최종 판단은 담당자 |

---

## 3. 동작 구조

```
[AI]        영상 → YOLOv8(사람 검출) → ByteTrack(추적) → 좌표(x, y) + ID
                                    ↓
[규칙 엔진]  좌표를 프레임마다 계산 → 6개 항목 점수화 → 위험도 + 판정 근거
```

AI는 **사람을 찾고 추적하는 역할만** 하고, 위험도와 그 근거는 직접 설계한 **규칙 엔진**이 계산합니다.
규칙 기반이므로 모든 점수의 이유를 설명할 수 있습니다 (Explainability).

### 판정 항목 (미행 의심 가점 · 총 100점)

| 항목 | 배점 | 핵심 판단 |
|---|---|---|
| 후방 근접 유지 | 15 | 후행자가 선행자 뒤쪽 일정 범위에 머문 비율 |
| 지속 시간 | 15 | 해당 관계가 일정 시간 이상 유지됐는지 |
| 방향 유사도 | 10 | 이동 방향이 지속적으로 유사한지 |
| 지연 경로 유사도 | 20 | 선행자의 **과거 위치**를 시간차를 두고 통과하는지 |
| 정지 후 추종 | 20 | 선행자가 멈춘 뒤 후행자가 **시간차를 두고** 멈추는지 |
| 방향 전환 추종 | 20 | 선행자의 방향 전환을 **시간차를 두고** 따라 하는지 |

각 항목은 측정값을 구간별 점수표로 환산합니다. (예: 후방 유지율 90% 이상 → 15점, 75~90% → 12점)

### 가중치를 10 / 15 / 20으로 나눈 기준

배점은 세 가지를 함께 봤습니다. ① 미행 판별에 대한 기여도, ② 정상 보행에서도 발생할 가능성,
③ 선행자 행동에 대한 후행자의 종속성. 이를 3단계로 정리했습니다.

| 단계 | 성격 | 해당 항목 |
|---|---|---|
| **10점** | 보조 특징 — 정상 상황에서도 흔하게 발생 | 방향 유사도 |
| **15점** | 기본 추종 특징 — 중요하지만 단독으로는 확정 불가 | 후방 근접 유지, 지속 시간 |
| **20점** | 핵심 행동 특징 — 선행자의 행동 변화에 후행자가 시간차를 두고 반응하는 **행동 종속성**이 나타남 | 지연 경로 유사도, 정지 후 추종, 방향 전환 추종 |

한 항목이 판정을 독점하지 않도록 최고 배점을 20점으로 제한했고,
반대로 어느 항목도 무의미해지지 않도록 최저 배점을 10점으로 두었습니다.

### 반응 시차 (1.5~4초)

정지·방향 전환 추종은 **후행자가 얼마나 늦게 반응했는지**로 판정합니다.

| 시차 | 해석 | 처리 |
|---|---|---|
| 0 ~ 0.5초 | 동행 또는 동일한 외부 환경에 대한 반응 | 감점 |
| 0.5 ~ 1.5초 | 판단 유보 | 점수 없음 |
| **1.5 ~ 4초** | **후행 반응 의심 구간** | **가점** |
| 4초 이상 | 두 행동의 관련성이 낮음 | 점수 없음 |

> 이 값은 사람의 생리적 반응시간을 정의한 것이 아닙니다.
> 정상 동행에서 나타나는 거의 동시적인 행동을 제외하기 위해 하한을 두고,
> 시간이 너무 길어지면 두 행동의 연관성이 떨어지므로 상한을 둔 **시스템의 초기 임계값**입니다.
> 이후 현장 데이터에 따라 보정할 수 있도록 설계했습니다.

### 동행 가능성 감점 (최대 -40점)

친구·연인·동료 등 정상 동행을 걸러내기 위한 장치입니다.

| 항목 | 감점 | 판단 |
|---|---|---|
| 나란히 이동 | -15 | 진행 방향 기준 좌우 간격이 일정하고 앞뒤 간격이 작음 |
| 행동 거의 동시 발생 | -10 | 정지·출발·회전 시차가 매우 짧음 (0~0.5초) |
| 선행·후행 역할 교대 | -10 | 앞뒤 위치가 여러 번 자연스럽게 바뀜 |
| 처음부터 함께 등장 | -5 | 화면 진입 시점과 위치가 유사 |

**최종 위험도 = 의심 가점 − 동행 감점**

#### 감점 상한을 40점으로 둔 이유

네 항목의 합이 우연히 40점이 된 것이 아니라, **상한을 먼저 정하고 항목을 배분**했습니다.

- 의심 가점이 만점(100점)인 구간이라도 감점 후 **60점이 남아 '확인 필요'(40~69점) 단계에 머물도록** 설계했습니다.
  동행 신호가 아무리 강해도 판정을 '일반 이동'까지 끌어내리지 않는다는 뜻입니다.
- 감점은 미행을 **부정하는 근거가 아니라 신중해지는 장치**입니다. 나란히 걷던 두 사람이
  이후 미행 관계로 바뀔 수도 있으므로, 감점만으로 구간을 완전히 지우지 않습니다.
- 즉 40점은 **"동행 신호가 판정을 뒤집지는 못하되, 우선순위는 낮춘다"** 는 선입니다.

### 위험도 단계

| 점수 | 단계 | 의미 |
|---|---|---|
| 70점 이상 | 우선 확인 | 담당자가 먼저 볼 구간 |
| 40 ~ 69점 | 확인 필요 | 여유가 될 때 확인 |
| 20 ~ 39점 | 의심 낮음 | 참고 |

### 오탐 저감 장치

1. **반응 신호 관문** — 정지·방향 전환 추종 중 하나 이상이 있어야 정식 결과로 올립니다.
   거리·방향·경로만으로는 '같은 길을 가는 사람'과 미행을 구별할 수 없기 때문입니다.
   (뒤에서 같은 속도로 걸으면 지연 경로 유사도가 100%까지 오릅니다 — 반응이 아니라 같은 길을 걸은 결과입니다.)
2. **반복 조건** — 같은 반응이 2회 이상일 때만 점수 부여 (횡단보도 등 우연한 동시 정지 방어)
3. **반응 시차 구분** — 0~0.5초는 동행 신호로 감점, 1.5~4초만 가점
4. **최소 공존 시간** — 두 사람이 일정 시간 이상 함께 보여야 분석 대상
5. **근접 후보 필터** — 일정 거리 안에 들어온 쌍만 비교 (사람이 많아도 연산량 제어)
6. **키 기준 정규화** — 픽셀이 아닌 사람 키 기준 거리 → 카메라 원근에 덜 민감

### 민감도 조절

현장 상황에 따라 걸러 내는 정도를 바꿀 수 있습니다. 판정 계산은 동일하고 **관문의 세기만** 달라집니다.

| 단계 | 점수 하한 | 의도 신호 | 반응 신호 | 쓰임 |
|---|---|---|---|---|
| 엄격 | 55점 | 2개 이상 | 1개 이상 | 확인할 여력이 적을 때 |
| **보통** | 40점 | 1개 이상 | 1개 이상 | 기본값 |
| 민감 | 25점 | 1개 이상 | 요구 안 함 | 넓게 훑어볼 때 |

## 4. 실행 방법

### 설치

```bash
pip install -r requirements.txt
```

### 실행

```bash
streamlit run app_v10.py
```

브라우저가 자동으로 열립니다. 열리지 않으면 `http://localhost:8501` 로 접속하세요.

> **처음 실행 시** YOLO 모델(`yolov8n.pt`, 약 6MB)이 자동으로 다운로드됩니다. 인터넷 연결이 필요합니다.

### 분석 모드

사이드바에서 전환합니다.

| 모드 | 동작 |
|---|---|
| **실분석** | YOLO로 실제 영상을 분석합니다. `cv2`·`ultralytics`와 가중치 파일이 필요합니다. |
| **데모** | 분석 없이 예시 결과로 화면만 확인합니다. 발표 리허설이나 UI 확인용입니다. |

의존 패키지가 없으면 자동으로 데모 모드로 내려가며, 화면에 사유를 표시합니다.

## 5. 화면 구성

| 화면 | 설명 |
|---|---|
| **영상 분석** | 영상 업로드 → 분석 → 결과 영상(추적 박스 표시), 위험 구간, 이벤트 타임라인, 위험도 그래프, 판정 근거 |
| **분석 기록** | 이전에 분석한 영상 목록 및 재열람 |
| **관제 알림** | 위험 구간이 영상별로 그룹화되어 누적되는 알림 로그 |

- 결과 영상에는 **미행 의심자는 코랄 박스(`id7 SUSPECT`), 일반 보행자는 민트 박스**로 표시됩니다.
- 이벤트 타임라인의 시간을 클릭하면 해당 장면부터 영상이 재생됩니다.
- 기준을 넘긴 구간이 없어도 **계산이 끝난 '참고 구간'을 제외 사유와 함께** 표시합니다.
  결과가 없는 이유를 확인할 수 있어야 하기 때문입니다.

## 6. 적용 범위와 한계

**MVP 적용 범위**
- 고정 CCTV, 화질이 양호한 저장 영상
- 단일 영상 파일 분석 (실시간 다중 CCTV 스트림은 범위 외)

**한계**
- 정상 동행(친구·연인·동료)도 선별될 수 있음 → 그래서 '확정'이 아닌 '우선순위 제시'로 설계
- 사람이 겹치거나 저조도 환경에서는 추적 ID가 끊길 수 있음
- 점수 가중치와 반응 시차 구간은 **실험적 초기값**이며, 현장 데이터 기반 보정이 필요함
- 자체 촬영 시나리오로 검증한 단계이며, 통계적으로 유의미한 정확도 측정은 남아 있음

**개인정보 보호**
- 얼굴 인식·신원 식별을 수행하지 않으며, **사람의 이동 궤적(좌표)만** 분석합니다.

## 7. 향후 방향

```
[현재]   업로드한 영상 분석 → 확인할 구간 선별                    (관제센터)
   ↓
[다음]   스토킹 신고 구간 영상 분석 → 확인 지점 선별              (수사 지원)
   ↓
[확장]   실시간 CCTV 연동 → 자동 분석 → 관제사에게 알림 전송
   ↓
[장기]   개인·소상공인 CCTV에서 반복되는 배회·미행 알림
```

판정 엔진은 그대로 두고 **쓰이는 곳만 바꾸는** 구조입니다.
실사용을 위해서는 기술 고도화와 함께 개인정보보호법 등 제도적 근거가 함께 마련되어야 합니다.
